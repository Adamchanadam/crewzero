# 你今次嘅工作：整理人物及機構名單

創辦人已確認嘅公司概覽提到一啲人同機構，但名單（`ledger.json` 嘅 `actors`）未有佢哋，或者類別未經核對。請你讀 `confirmed-page.md`（已確認嘅公司概覽）同 `people.md`（整理名單嘅材料：「已有人負責的事」原文、公司以外的決策者、各站要點頭的人、現有名單、創辦人已答「不加入」嘅名稱），然後寫 `out/people.json`。你只可以寫 `out/`。

## 交回格式（`out/people.json`）

```json
{
  "summary": "一句：建議加入幾個人、更正幾個類別",
  "items": [
    { "kind": "newActor", "name": "陳小明", "role": "送貨及日常營運", "actorKind": "team", "teamType": "fulltime", "why": "已有人負責的事寫明他已答應加入，負責送貨及日常營運。" },
    { "kind": "newActor", "name": "王伯", "role": "農務顧問", "actorKind": "advisor", "why": "已有人負責的事寫明他是顧問，負責農務意見，不負責營運。" },
    { "kind": "actorKind", "name": "丙農場主", "actorKind": "partner", "why": "丙農場是供貨伙伴，不是客戶。" }
  ]
}
```

## 規矩

1. **只可以用公司概覽原文有嘅名字。** `name` 必須**逐字**出現喺 `confirmed-page.md` 或 `people.md` 嘅原文入面（唔好用代稱、簡稱、譯名或自己補全）；唔喺原文嘅名字一律唔寫。冇需要補充就交空清單 `"items": []`。
2. **創辦人本人唔寫入名單**：「我自己」「我」「本人」同「我自己（某某）」括號內嘅名字都係創辦人，唔好建議。
3. **現有名單已有嘅名稱（含另一個稱呼）唔好再建議加入**；創辦人已答「不加入」嘅名稱亦唔好再提。
4. `newActor` 項目：`actorKind` 係 `customer`（客戶）、`partner`（供應或合作方）、`investor`（投資者或資助方）、`advisor`（顧問或協助者）、`team`（團隊成員）之一；揀 `team` 要加 `teamType`（`cofounder` 共同創辦人、`fulltime` 全職、`parttime` 兼職、`contractor` 外判；原文冇講就按上下文判斷，寫唔到就 `parttime`）同 `role`（佢負責乜，最多 40 字）；`org` 可省略；`why` 一句（最多 200 字）引述原文邊度提到佢。
5. `actorKind` 項目（更正舊類別）：只針對 `people.md`「現有名單」標「類別未經核對」嘅對象，`name` 寫名單入面嘅名稱，`actorKind` 寫你判斷嘅類別（同現有類別一樣就唔使寫）；改為 `team` 要加 `role`。例如報社、合作機構嘅主管係「供應或合作方」，出錢嘅係「投資者或資助方」，俾意見唔負責營運嘅係「顧問或協助者」。
6. **只可以寫名稱、機構同角色：唔好寫電話、電郵、地址、社交帳號、薪酬、合約或任何人事資料**（寫咗會被退回）。
7. 團隊成員優先，其次顧問、投資者、合作方、客戶；每類逐個列，唔好合併幾個人做一項。
