# 商業模式卡

這份資料供 Zero 分析創辦人的生意構想時選用。它按收錢方式、供應形態和擴展方法整理可比較的模式，協助提出有根據的判斷。

## 1. 使用規則

- **三個面向：** 先把收錢方法、供應形態和擴大方法分別判斷，三方面每項至少對應一張卡；一門生意通常會把兩至三種模式結合。
- **先判定目標：** 先確認想做成哪種生意，再衡量模式是否合用；高速增長不是唯一尺度。
- **盡快有收入：** 優先查看能較早收到款項的模式，例如專業服務、產品化服務、預收款／預售或一次性購買。
- **小而穩的生意：** 以穩定利潤和較低風險為重，不建議必須高速擴張才可成立的組合。
- **高速擴張：** 優先考慮收入不必跟人手同步增加的做法，並同時檢視現金消耗。
- **準備融資：** 進展應按下一輪投資者要看的證據衡量，例如留存、試點或意向書；長時間仍把收入列為「假設」可以是正常狀況，不應因此催促提早收費。投資者出資只代表有人願意投資，不會推進客戶、價值主張或收入各格；不在此評估估值或處理投資條款。
- **未定：** 依創辦人的原話提出建議；若沒有足夠線索，明記「未定」，並以一般標準分析，不能假定其目標是高速擴張。
- **選卡依據：** 每選一張卡，逐字引用該卡一條適合信號，並標示支持它的創辦人原話出處。某面向資料不足時寫「未定」，說明欠缺的資料及取得方式。
- **收入的判斷：** 收入類假設須寫清楚付款者；只有該方付款、付訂金、落單或簽約，收入格才成立。免費增值、廣告和雙邊市場的免費使用者註冊或使用，只屬實際行動，可推進價值主張、客戶或渠道等格，不能推進收入格。
- **補充模式：** 主要組合應以核心模式卡為本；補充模式只作替代或補強。若使用補充模式，其最大陷阱和第一個驗證由 Zero 撰寫並標為「Zero 建議」，不可當成卡片引文。
- **編號與數字：** 編號只作內部對照，面向創辦人的文字只用模式名稱。第一個驗證中的人數和期限均屬 Zero 建議，引用時要標示「Zero 建議」，不可填入生意模式圖九格；指標詞彙的業界參考線只供 Zero 判斷，不能寫給創辦人。

## 2. 診斷問題

| 問題 | 答「是」時優先考慮 |
|---|---|
| 顧客是否會按週或按月反覆出現同一需求？ | 訂閱制、會員與忠誠計劃、連網裝置＋持續服務 |
| 各個顧客的使用量是否相差很遠？ | 按用量收費、混合定價 |
| 成果能否明確量度，亦能證明由你帶來？ | 按成果收費、AI 代辦成果 |
| 使用產品時，會否持續消耗耗材、配件或內容？ | 剃刀與刀片、連網裝置＋持續服務 |
| 付款或交易是否必須經過你的位置？ | 交易抽成、垂直軟件＋支付 |
| 兩批各自分散、互相需要的人，是否難以自行找到對方？ | 雙邊市場／平台 |
| 提供免費基本版的單位成本是否近乎零？ | 免費增值、開源／開放核心 |
| 顧客會否願意先繳款，再等待交付？ | 預收款／預售 |
| 創辦人是否具備可信專長及既有追隨者？ | 專業服務、知識產品與付費社群 |
| 重複服務能否把範圍及價格都固定下來？ | 產品化服務、AI 代辦成果 |
| 目標買方是否屬大機構，且單份合約金額較大？ | 企業銷售 |
| 品牌、內容、設計或技術等資源，是否難以被競爭者複製？ | 授權／知識產權、深科技／硬科技 |
| 產品價格高而使用次數不多嗎？ | 租用代替購買、共同擁有 |
| 單店或單位是否已證明可獲利，並能整理為標準流程？ | 特許經營、店中店 |
| 使用者數量多且常用，但他們本身不想付款嗎？ | 廣告／第三方付費、數據變現 |
| 你能繞過抽成偏高的中間商，直接接觸顧客嗎？ | 網上直銷 |

## 3. 指標詞彙

| 指標 | 意思 | 算法 |
|---|---|---|
| 每月經常性收入（MRR） | 按月重複而可望取得的收入 | 所有有效訂閱的月費總和 |
| 年度經常性收入（ARR） | 把每月經常性收入換算成全年的數值 | MRR × 12 |
| 月流失率 | 每月取消的顧客在月初顧客中的比例 | 本月取消的顧客數 ÷ 月初顧客數 |
| 淨收入留存率（NRR） | 比較同一批原有顧客現時收入與一年前收入的比率 | （一年前那批顧客現在的收入）÷（他們一年前的收入）；高於 100% 即原有顧客增購多於流失 |
| 獲客成本（CAC） | 平均取得一名付費顧客所花的支出 | 期內推廣及銷售總支出 ÷ 期內新增付費顧客數 |
| 顧客終身價值（LTV） | 顧客關係持續期間可帶來的毛利 | 每位顧客每月毛利 ÷ 月流失率 |
| LTV/CAC | LTV 相對 CAC 的回報倍數，即每付出一元獲客成本可賺回多少 | LTV ÷ CAC；業界健康參考常用 3 倍 |
| 獲客成本回本期 | 賺回獲客成本所需的月數 | CAC ÷ 每位顧客每月毛利；業界參考通常為 12 個月內 |
| 毛利率 | 收入扣掉直接成本後，每一元所餘的比例 | （收入 − 直接成本）÷ 收入 |
| 交易總額（GTV）／成交總額（GMV） | 經你處理或平台上完成交易的總額，不等於你的收入 | 期內所有交易金額總和 |
| 抽成率 | 你在每宗交易收取的收入佔交易金額的比率 | 你的收入 ÷ GMV 或 GTV |
| 年度合約金額（ACV） | 按合約年期折算後的每年平均金額 | 合約總額 ÷ 合約年期 |
| 每位用戶平均收入（ARPU） | 平均每位用戶帶來的收入 | 期內收入 ÷ 期內活躍用戶數 |
| 每日／每月活躍用戶（DAU／MAU） | 在指定的每日或每月期間內，至少曾使用產品一次的用戶人數 | 期內至少使用一次的不重複用戶數 |
| 轉換率 | 由上一個階段進入下一個階段的人數比例 | 下一階段人數 ÷ 上一階段人數，如付費用戶 ÷ 免費用戶 |
| 回購率 | 曾購買顧客之中再次購買的比例 | 期內再次購買的顧客數 ÷ 期內曾購買的顧客數 |
| 資產使用率 | 資產可用時間中用於賺錢的比例 | 實際出租或使用時間 ÷ 可用時間 |
| 可計費時數比例 | 員工總工時中可向客戶收費的比例 | 可收費工時 ÷ 總工時 |

## 4. 核心模式卡

每張卡均說明賺錢原理、適用與不適用的信號、應看的數字、常見風險、低成本測試和可配搭的模式。關鍵指標的算法見指標詞彙。模式名稱用中文通稱；有英文原名的另列「英文名」，只供對照，畫面標籤只用中文名。

### 4.1 怎樣收錢

#### 訂閱制

- 編號：C01
- 英文名：Subscription
- 核心邏輯：要持續取得產品或服務，顧客須按固定周期繳付固定費用；收入是否可預測則取決於顧客是否留下。
- 適合信號：
  - 顧客的需求每週或每月再度出現。
  - 使用時間愈長，價值愈高，例如資料不斷累積或使用習慣逐漸形成。
  - 內容或功能可持續更新。
- 不適合信號：
  - 需求只發生一次或極少發生。
  - 顧客只想解決一個單次問題。
- 關鍵指標：每月經常性收入、月流失率、淨收入留存率、顧客終身價值與獲客成本比率、獲客成本回本期
- 常見陷阱：
  - 持續價值不足，顧客試用後便取消。
  - 取得顧客的前期支出很大，收入卻逐月回收，造成現金不足。
  - 只追求新顧客而忽略留存。
- 第一個驗證：請約 10－20 位目標顧客參加首月收費試用，統計付款者及第二個月繼續付款者。
- 常見組合：免費增值、混合定價、會員與忠誠計劃、網上直銷

#### 按用量收費

- 編號：C02
- 英文名：Usage-based／Pay per use
- 核心邏輯：顧客依實際用量付費，用得愈多，收入愈高。
- 適合信號：
  - 顧客之間的實際用量相距很大。
  - 主要由其他軟件或系統使用，而不是由人手操作。
  - 顧客希望先從小量使用開始。
- 不適合信號：
  - 若主要由人使用，而使用者又不願持續核算用量，訂閱通常較合適。
  - 顧客需要固定預算。
- 關鍵指標：淨收入留存率、毛利率、每位顧客用量增長
- 常見陷阱：
  - 顧客的淡旺季使收入大幅起伏。
  - 用量上升時直接成本同步上升，壓低毛利。
  - 為免帳單超出預期，顧客會減少使用。
- 第一個驗證：先向少量顧客採取逐次計費，於一個月內統計用量分布和帳單爭議數目。
- 常見組合：混合定價、API／基礎設施、訂閱制

#### 按成果收費

- 編號：C03
- 英文名：Outcome-based／Performance-based
- 核心邏輯：收費安排以約定成果為準：成功處理一宗查詢或帶來一名合資格客戶後，才產生費用。
- 適合信號：
  - 成果可清楚量度。
  - 可把成果歸因於你的工作。
  - 新方案令顧客猶疑，須以完成才付款作保證。
- 不適合信號：
  - 成果受大量外部因素左右。
  - 對何謂成功，雙方未能達成共同標準。
- 關鍵指標：成果數量、每個成果的毛利、成果爭議比率
- 常見陷阱：
  - 顧客認為成果與你的工作無關，引起歸因爭議。
  - 顧客本身的經營狀況會影響收入。
  - 為追求較多成果而降低品質。
- 第一個驗證：試行協議的顧客人數定為 1 至 3 位，為期一個月；協議預先以書面訂明成果及量度方式，期間記錄爭議個案。
- 常見組合：混合定價、AI 代辦成果

#### 混合定價

- 編號：C04
- 核心邏輯：先以固定底費穩住基本收入，再為超額用量或成果收費，兼顧穩定性和價值掛鈎。
- 適合信號：
  - 成本結構既有固定部分，亦有隨用量而增減的部分。
  - 顧客雖要求預算可預計，仍可接受用得較多便付得較多。
- 不適合信號：
  - 顧客群規模小，所有人都只需要簡單價目。
- 關鍵指標：底費佔總收入比例、超額收入、毛利率
- 常見陷阱：
  - 若價格安排令人難以作比較或估算支出，成交便可能延後。
- 第一個驗證：向目標顧客 10 位展示一至兩個價格方案，測試他們能否於一分鐘內說出月費約數，並記錄願意簽約的人數。
- 常見組合：訂閱制、按用量收費、按成果收費、AI 代辦成果

#### 交易抽成

- 編號：C05
- 英文名：Transactional
- 核心邏輯：你負責資金流或交易流程，從每筆交易取一小部分費用。
- 適合信號：
  - 付款或交易必須通過你的位置。
  - 交易發生頻繁。
  - 顧客重視便利和可靠。
- 不適合信號：
  - 交易次數不多。
  - 付款可由顧客直接完成，無須經過你。
- 關鍵指標：交易總額、抽成率、淨收入、回頭使用率
- 常見陷阱：
  - 每筆交易的利潤很薄，必須累積很多交易才有可觀收入。
  - 即使只發生一次錯誤或保安事故，亦可能令信任流失。
- 第一個驗證：先以人手為少量顧客處理交易，了解他們是否願為方便而付抽成，以及可接受的水平。
- 常見組合：垂直軟件＋支付、雙邊市場／平台

#### 免費增值

- 編號：C06
- 英文名：Freemium
- 核心邏輯：讓大量用戶先使用免費基本版，再由其中少數購買進階版，以這些付費收入支持運作。
- 適合信號：
  - 每名免費用戶帶來的服務成本近乎零。
  - 部分用戶會認為進階功能有明顯額外價值。
  - 用戶會自行轉介。
- 不適合信號：
  - 每位用戶均帶來明顯的服務開支，例如人手和實物；其他明顯的服務開支亦包括在內。
  - 目標顧客數量太少，不能依賴大批免費用戶轉為付費。
- 關鍵指標：免費轉付費轉換率、每位免費用戶成本、由註冊到付費所需時間
- 常見陷阱：
  - 免費版已足夠使用，無人升級。
  - 免費用戶成本耗盡現金。
  - 免費與付費的分界含糊。
- 第一個驗證：要選定收費功能，先讓用戶使用免費版；再把最常被要求的功能列為收費項目，並記錄轉換率。
- 常見組合：訂閱制、開源／開放核心、廣告／第三方付費

#### 剃刀與刀片

- 編號：C07
- 英文名：Razor and Blade
- 核心邏輯：主產品以低價甚至免費降低購買門檻，從持續購買且高毛利的耗材或內容收回補貼。
- 適合信號：
  - 耗材、配件或內容會在產品使用過程中反覆用掉。
  - 耗材能與主產品綁定。
- 不適合信號：
  - 市面容易取得便宜的相容耗材。
  - 顧客只會使用一次。
- 關鍵指標：主產品售出數量、耗材回購率、耗材毛利、每位顧客終身耗材收入
- 常見陷阱：
  - 顧客改用便宜相容耗材，主產品補貼無法收回。
  - 綁定過度會引起顧客反感。
- 第一個驗證：先按主產品讓利（補貼）的金額，計算每位顧客須再購買多少次耗材才能收回這筆讓利；再把產品賣給第一批顧客，並在三個月內記錄他們實際再購買耗材的次數。
- 常見組合：鎖定、連網裝置＋持續服務、訂閱制

#### 附加銷售

- 編號：C08
- 英文名：Add-on
- 核心邏輯：基本產品以具競爭力的價格出售，另設多項可加購選擇，使顧客最終支出高於最初預期。
- 適合信號：
  - 顧客的需要各有不同。
  - 加購項目通常成本不高，卻可帶來較高毛利。
  - 顧客比較方案時，往往先看基本價格。
- 不適合信號：
  - 顧客極重視價格透明。
  - 若沒有加購便不能滿足基本需要，便不適合採用。
- 關鍵指標：加購比率、每位顧客平均收入
- 常見陷阱：
  - 把不可或缺的項目另列加購，會令顧客感到受騙並損害口碑。
- 第一個驗證：測試方法是把兩至三項加購選擇放進現有銷售過程；試行一個月後，統計加購比率和投訴。
- 常見組合：網上直銷、訂閱制、產品化服務

#### 預收款／預售

- 編號：C09
- 英文名：Cash Machine／Pre-sale
- 核心邏輯：這種做法讓顧客先付款，交付安排留待其後；款項可支援生產或營運，同時用以驗證需求。
- 適合信號：
  - 需求已有初步信號。
  - 可明確承諾交付時間。
  - 生產需先投入資金。
- 不適合信號：
  - 交付時間未能確定。
  - 產品尚未有可展示的樣本。
- 關鍵指標：預收金額、準時交付率、退款率
- 常見陷阱：
  - 交付延誤會傷害信譽。
  - 預先收取的款項改作其他用途，最終不能完成交付。
- 第一個驗證：預訂的測試可採用訂金或群眾集資；最低目標數量需預先訂明，若未達到便全額退款。
- 常見組合：網上直銷、訂閱制、大量訂製

#### 會員與忠誠計劃

- 編號：C10
- 英文名：Membership／Customer Loyalty
- 核心邏輯：顧客付費入會或累積積分，以換取會員專屬好處；顧客因而較常光顧，且每次消費更多。
- 適合信號：
  - 顧客購買頻率高。
  - 可向會員提供獨特好處，例如價格、優先權或專屬產品。
- 不適合信號：
  - 顧客一年只買一兩次。
  - 好處容易被競爭者複製。
- 關鍵指標：會員續期率、會員消費頻率、會員與非會員的消費差距
- 常見陷阱：
  - 優惠的成本超出它帶來的額外消費。
  - 會員好處缺乏吸引力，續期率偏低。
- 第一個驗證：向現有熟客試行收費會籍或積分方案，為期三個月；比較入會者與未入會者的消費相差多少。
- 常見組合：網上直銷、訂閱制、體驗銷售

#### 廣告／第三方付費

- 編號：C11
- 英文名：Advertising／Hidden Revenue
- 核心邏輯：使用者不用付費，改由想接觸這群人的第三方提供收入，例如廣告商。
- 適合信號：
  - 用戶量大而且使用頻繁。
  - 用戶群對某類廣告商有清楚價值。
- 不適合信號：
  - 用戶數量太少。
  - 用戶群過於分散，廣告商難以準確接觸。
- 關鍵指標：每日／每月活躍用戶、每位用戶平均收入
- 常見陷阱：
  - 這類收入須有非常龐大的用戶數目才具份量；新公司只靠這一種收入而成功的情況相對少。
  - 廣告過多會趕走用戶。
- 第一個驗證：先累積用戶群，然後邀請一至兩個相關程度很高的贊助商試行，查看其付款意願。
- 常見組合：免費增值、數據變現、知識產品與付費社群

#### 授權／知識產權

- 編號：C12
- 英文名：License
- 核心邏輯：把資源投放於品牌、內容、技術或設計，讓他方取得使用權並支付授權費或分成。
- 適合信號：
  - 品牌、內容、設計或技術如不易仿製，便具備授權的條件。
  - 若自行把產品造出來或賣出去的代價偏高，可考慮授權。
- 不適合信號：
  - 他人很容易規避或仿製該知識產權。
  - 沒有能力追究侵權。
- 關鍵指標：授權收入、授權方數目、續約率
- 常見陷阱：
  - 維護知識產權需要很高成本。
  - 只靠少數授權方帶來大部分收入，風險過於集中。
- 第一個驗證：找一至兩家可能取得授權的機構，提出使用範圍及期限均有限的授權試行，並了解對方是否願意付款。
- 常見組合：深科技／硬科技、白牌、成分品牌

### 4.2 賣甚麼形態

#### 網上直銷

- 編號：C13
- 英文名：Direct-to-Consumer／D2C
- 核心邏輯：在沒有中間商的情況下直接面向消費者，原有差價得以保留，顧客資料和關係亦由自己掌握。
- 適合信號：
  - 品牌故事清晰。
  - 中間商抽成偏高。
  - 網上和社交媒體可讓你繞過中間環節，直接接觸顧客。
- 不適合信號：
  - 顧客在實體店完成比較後才作購買決定。
  - 售價不高，但運費偏高。
- 關鍵指標：獲客成本、毛利率、回購率、顧客終身價值與獲客成本比率
- 常見陷阱：
  - 網上廣告成本持續增加，使獲客愈來愈昂貴。
  - 物流、存貨與退貨帶來很大壓力。
- 第一個驗證：先選網店或社交媒體其中一種渠道，以小批量產品測試銷售；少額推廣後，核算首月的獲客成本及毛利。
- 常見組合：訂閱制、會員與忠誠計劃、預收款／預售

#### 產品化服務

- 編號：C14
- 英文名：Productized Service
- 核心邏輯：把服務範圍、價錢和交付時間全部定為固定，如同現成產品般出售；藉此省下逐次報價及來回溝通的成本。
- 適合信號：
  - 同類服務重複出現。
  - 顧客擔心報價不透明。
  - 交付流程可標準化。
- 不適合信號：
  - 各個項目的差異很大，無法訂出固定範圍。
- 關鍵指標：每單毛利、每單實際工時、續單率
- 常見陷阱：
  - 服務範圍界定過闊時，投入的工時容易超出控制。
  - 範圍之外的修改若被一再提出，產品化服務未必合適。
- 第一個驗證：把最常見的服務整理成一頁報價資料，寫明範圍、價格、交付日數與除外項目；向潛在顧客 10 位報價，統計成交數和實際工時。
- 常見組合：訂閱制、AI 代辦成果、附加銷售

#### 專業服務

- 編號：C15
- 核心邏輯：按項目或工作時間計費，出售專業人手及判斷。
- 適合信號：
  - 創辦人擁有稀缺專業。
  - 需要盡快取得收入。
  - 希望日後把服務產品化，現階段便需要深入認識客戶。
- 不適合信號：
  - 目標是高速擴張。
  - 專業容易被取代。
- 關鍵指標：可計費時數比例、每位員工收入、最大客戶佔總收入比例
- 常見陷阱：
  - 要擴大收入便必須同時增加人手，顯示擴張受限。
  - 過度依賴少數大客戶。
  - 長期無法抽身發展產品。
- 第一個驗證：透過既有人脈取得一至兩個收費項目，記下項目中反覆出現的工作，再判斷能否轉成產品化服務或 AI 代辦成果。
- 常見組合：產品化服務、AI 代辦成果、知識產品與付費社群

#### AI 代辦成果

- 編號：C16
- 英文名：Services-as-Software
- 核心邏輯：顧客取得的是 AI 代理完成服務後的結果，不是自行操作的工具；計費一般依成果或採取混合方式。
- 適合信號：
  - 現有服務由人手完成，流程重複且成果可核對。
  - 工具本身並非顧客付費的目的；他們要的是成果。
- 不適合信號：
  - 若涉及法律或醫療的最終判斷等高度專業責任，不適合使用。
  - 難以由人手覆核而失誤代價又極高時，不適合使用。
- 關鍵指標：每個成果的成本、需要人手介入的比率、續約率
- 常見陷阱：
  - 品質不穩定會很快失去信任。
  - 成果歸因容易引起爭議。
  - 人手介入比例偏高時，會蠶食毛利，令結果低於預期。
- 第一個驗證：先讓 AI 配合人手覆核，向三至五位顧客交付結果；記下每項成本和人手介入的比率。
- 常見組合：按成果收費、混合定價、產品化服務

#### 企業銷售

- 編號：C17
- 英文名：Enterprise
- 核心邏輯：銷售予大型機構的年度合約金額較高，常見年額在數十萬美元以上。
- 適合信號：
  - 大型機構所面對的重要問題能由產品處理。
  - 投資回報可計算並證明。
  - 團隊能承受較長的銷售周期。
- 不適合信號：
  - 現金可支撐的時間很短。
  - 產品尚未穩定。
  - 團隊缺乏向企業銷售的經驗。
- 關鍵指標：年度合約金額、銷售周期、銷售管道金額、試點轉正率
- 常見陷阱：
  - 從接觸至簽約的過程很長，且須多位決策者同意；合約尚未簽成，現金已用完。
  - 對某一客戶訂製過多，令產品失焦。
- 第一個驗證：嘗試取得一至兩個收費試點，並在開始前以書面訂下成為正式合約的條件。
- 常見組合：訂閱制、按成果收費、API／基礎設施

#### 垂直軟件＋支付

- 編號：C18
- 核心邏輯：先向特定行業供應日常經營軟件，然後以貸款、支付等金融服務取得主要收入。
- 適合信號：
  - 目標行業的交易頻繁。
  - 商戶的日常工作已在你的軟件內完成。
  - 行業缺少專用軟件。
- 不適合信號：
  - 無法取得金融牌照。
  - 找不到支付夥伴。
  - 行業交易量很小。
- 關鍵指標：支付交易額、金融收入佔總收入比例、商戶留存
- 常見陷阱：
  - 取得金融牌照及滿足合規要求的門檻很高。
  - 呆帳及詐騙風險。
- 第一個驗證：先把軟件推出，並接通既有支付服務商的收款安排，再觀察願意改用的商戶數目。
- 常見組合：訂閱制、交易抽成

#### API／基礎設施

- 編號：C19
- 英文名：Layer Player
- 核心邏輯：只專精整條價值鏈的一個環節，讓不同行業的許多公司接駁使用，並以規模和專業取勝。
- 適合信號：
  - 多個行業都需某一環節，而自行開發很困難或成本高。
  - 買方為開發者或技術團隊。
- 不適合信號：
  - 大型平台能輕易自行製作同類功能。
- 關鍵指標：調用量、淨收入留存率、開發者啟用率（已註冊開發者中真正完成接入的比例）
- 常見陷阱：
  - 大型平台若能自行加入同類功能，可能令你的服務失去位置。
  - 陷入價格競爭。
- 第一個驗證：提供簡短文件及免費額度，請開發者 10 位試接；統計一週內接入完成並開始付款的人數。
- 常見組合：按用量收費、混合定價、企業銷售

#### 開源／開放核心

- 編號：C20
- 英文名：Open Source／Open Core
- 核心邏輯：核心軟件讓任何人免費使用及改進；收入由技術支援、進階功能或託管服務帶來。
- 適合信號：
  - 用戶大多是開發者。
  - 社群可協助推廣及改進。
  - 企業客戶除產品外，還需要支援與服務保證。
- 不適合信號：
  - 產品不是軟件。
  - 團隊無力經營社群。
- 關鍵指標：社群活躍度、商業版轉換、企業客戶數
- 常見陷阱：
  - 免費版已經足夠，無人付款。
  - 你的開放軟件可成為大型雲端服務商對外提供服務的直接基礎。
- 第一個驗證：發布開放核心版本，統計正式環境採用的機構數，再向最活躍的幾家提出收費支援。
- 常見組合：免費增值、訂閱制、企業銷售

#### 租用代替購買

- 編號：C21
- 英文名：Rent Instead of Buy
- 核心邏輯：租用可降低顧客最初支出；公司則在整段租期收費，讓資產的使用效率上升。
- 適合信號：
  - 產品價格昂貴而使用有限，或必須定期更新換代。
- 不適合信號：
  - 產品價格低。
  - 損耗快且維修成本高。
- 關鍵指標：資產使用率、每件資產回本期、損耗率
- 常見陷阱：
  - 資產的折舊、維修及物流支出常被估得過低。
  - 購置資產需要大量前期資金。
- 第一個驗證：先以少量資產開放出租，記錄整整三個月的使用率及維修開支，再以這些數字計算回本所需時間。
- 常見組合：訂閱制、共同擁有、連網裝置＋持續服務

#### 知識產品與付費社群

- 編號：C22
- 核心邏輯：知識產品可包括課程、付費通訊或社群會籍；製作一次後，便能多次向顧客銷售。
- 適合信號：
  - 創辦人具備可信專業。
  - 已有一批追隨者。
  - 若目標顧客把學習或加入圈子視為值得付費，可考慮。
- 不適合信號：
  - 創辦人未有公開影響力。
  - 內容很快失去時效，卻無力持續更新。
- 關鍵指標：學員或訂戶數、完成率、轉介率
- 常見陷阱：
  - 收入依賴創辦人個人。
  - 內容過時。
  - 學員未能完成的比例偏高，會削弱口碑。
- 第一個驗證：以預售方式推出一個小規模課程或收費社群，並預先訂明開辦所需的最低報名人數。
- 常見組合：訂閱制、預收款／預售、專業服務

#### 連網裝置＋持續服務

- 編號：C23
- 核心邏輯：裝置記錄使用情況，或自動下單補充；公司的主要收入來自其後提供的服務、數據分析或耗材。
- 適合信號：
  - 可感測產品使用狀況。
  - 存在持續監測或反覆補充的需求。
- 不適合信號：
  - 硬件成本太高，顧客亦不願預先付款。
  - 資料沒有額外價值。
- 關鍵指標：裝置數量、服務附加率、自動續訂率
- 常見陷阱：
  - 硬件研發和生產成本偏高。
  - 資料私隱問題。
  - 裝置故障會拖累服務收入。
- 第一個驗證：先確認顧客是否有為持續服務付費的意願，才投資硬件；感測與自動下單可先由人手代替，例如定期詢問補貨。
- 常見組合：訂閱制、剃刀與刀片、鎖定

#### 深科技／硬科技

- 編號：C24
- 英文名：Deep Tech／Hard Tech
- 核心邏輯：利用科學或工程的突破形成不易仿製的優勢，開拓原先未有的市場。
- 適合信號：
  - 有關鍵技術在手或具備研究團隊。
  - 技術成功後的市場清晰。
  - 可取得長期資金。
- 不適合信號：
  - 可動用資金可支撐的時間在一年以內。
  - 市場需求尚未確認。
- 關鍵指標：技術里程碑、顧客或夥伴的意向書、資金跑道（現有現金可支撐營運的月數）
- 常見陷阱：
  - 資金跑道短於完成研發所需的時間。
  - 技術成功卻沒有市場。
- 第一個驗證：在投入大量研發前，向可能的顧客或合作夥伴取得意向書，以確認技術完成後會有人付款。
- 常見組合：授權／知識產權、企業銷售

### 4.3 怎樣擴大

#### 雙邊市場／平台

- 編號：C25
- 英文名：Two-sided Market／Marketplace
- 核心邏輯：把兩組互有需要的人連起來，並從配對或交易取費；一方人數增加會提升另一方價值。
- 適合信號：
  - 兩方同樣分散，並不容易自行相遇。
  - 配對帶來清楚價值。
  - 可在平台內完成交易。
- 不適合信號：
  - 任一方高度集中。
  - 平台若促成一次交易後，雙方可不再經平台而長期交易。
- 關鍵指標：成交總額、抽成率、配對成功率、兩邊留存率
- 常見陷阱：
  - 平台兩邊起步時皆無參與者，因而面對先有雞還是先有蛋的難題。
  - 兩方跳過平台，私下完成交易。
- 第一個驗證：只在一個小地區或一個細分類別試行；由人手招募供應方，並由人手為雙方配對；記錄成交數目及雙方的回頭率。
- 常見組合：交易抽成、免費增值、聯盟分銷

#### 特許經營

- 編號：C26
- 英文名：Franchising
- 核心邏輯：加盟商取得品牌、產品及營運做法的使用許可，負責出資及承擔本地風險；總部則收取加盟費和營業額分成。
- 適合信號：
  - 單店模式已證明可獲利。
  - 可把營運做法編成標準流程及培訓材料。
  - 品牌有吸引力。
- 不適合信號：
  - 單店仍未穩定獲利。
  - 成效取決於創辦人本人。
- 關鍵指標：加盟店數、單店盈利、加盟費及分成收入
- 常見陷阱：
  - 難以管控品質，一間分店出問題便會連累整個品牌。
  - 標準流程尚未成熟便過早擴張。
- 第一個驗證：能否維持業績，可由非創辦人的員工進行一段時間的獨立經營來測試；他們須按自營店做法整理的手冊執行。
- 常見組合：授權／知識產權、店中店

### 5.1 怎樣收錢

| 編號 | 模式 | 英文名 | 說明 | 何時考慮 |
|---|---|---|---|---|
| S01 | 一次性購買 |  | 購入產品或服務時由顧客一次過付清。 | 適合零售、小店和低頻需求，也可作其他模式的起點。 |
| S02 | 自訂價格 | Pay What You Want | 付款額由顧客決定，亦可設定最低或建議價格。 | 若數碼產品幾乎不因增加使用者而增加成本，並希望吸引許多新顧客。 |
| S03 | 打賞／捐助 |  | 先免費提供服務或項目，認同者可自願付款支持；內容及公益項目是其中例子。 | 已有忠實支持者的內容或公益項目可考慮採用。 |
| S04 | 拍賣 | Auction | 物品售予出價最高者。 | 當貨品稀有而難以預先判定其價值時，可考慮拍賣。 |
| S05 | 收入分成 | Revenue Sharing | 把合作所增加的收入與夥伴分配。 | 靠合作夥伴帶來顧客或內容，且雙方都不想預先付一筆固定費用。 |
| S06 | 交叉補貼定價 | Robin Hood | 較富裕顧客支付較高價格，以補貼基層顧客的較低價格。 | 若社會使命亦獲高端顧客認同，這個定價方法才合適。 |
| S07 | 數據變現 | Leverage Customer Data | 善用顧客資料提高本身效益，或把資料提供予第三方。 | 手上已累積大量有價值的顧客行為數據，且已取得顧客同意。 |
| S08 | 鎖定 | Lock-in | 透過提高轉換成本使顧客持續留用。 | 產品之間已有技術綁定時，常可與剃刀與刀片並用。 |
| S09 | 物物交換 | Barter | 雙方不以金錢結算，而是互換各自重視的價值；例如可用產品換取曝光。 | 起步時現金不足，卻能提供對方所需的產品或服務。 |
| S10 | 保證可用 | Guaranteed Availability | 承諾服務幾乎不會停機，並按服務水平取費。 | 停機會令顧客有重大損失，而你憑規模或專業可減少停機。 |

### 5.2 賣甚麼形態

| 編號 | 模式 | 英文名 | 說明 | 何時考慮 |
|---|---|---|---|---|
| S11 | 體驗銷售 | Experience Selling | 用體驗提高產品感受價值，從而支撐較高價格。 | 產品相近時，可憑環境、服務或故事作出區別。 |
| S12 | 極致奢華 | Ultimate Luxury | 只服務最高端的顧客，提供品質極高且高毛利的產品或服務。 | 有獨有工藝或稀少資源，並能接觸高端客群。 |
| S13 | 極簡低價 | No Frills | 僅留下核心價值，把節省到的成本讓利予顧客。 | 客群重視價格，而現有產品包含很多不需要的部分。 |
| S14 | 服務基層 | Target the Poor | 服務購買力較低的顧客，以量取勝。 | 既有高價產品未能覆蓋的顧客數量龐大時，可考慮服務基層。 |
| S15 | 大量訂製 | Mass Customization | 以模組化生產配合個人需要，同時保持具競爭力的價格。 | 產品可拆成標準模組而顧客又要求個人化時。 |
| S16 | 用家設計 | User Designed | 平台讓顧客使用工具設計及出售自己的產品。 | 顧客想創作，而你可負責生產或銷售。 |
| S17 | 用家同時生產 | Prosumer | 顧客同時擔當生產者，並從其產出取得好處。 | 顧客擁有可分享的作品或資源，例如內容或電力。 |
| S18 | 數碼化 | Digitization | 將實物產品或服務改為數碼形式。 | 實體分發成本高，而改成數碼版本後，顧客感受到的價值不會減少。 |
| S19 | 虛擬化 | Virtualization | 把原本須在實體完成的流程移至網上，令顧客不受時間和地點限制。 | 顧客現時要親身到場，但實際並非必要。 |
| S20 | 自助 | Self-service | 以較低價格作交換，部分工序由顧客自行完成。 | 如部分工序成本高，交由顧客處理反而更快。 |
| S21 | 一站式方案 | Solution Provider | 顧客在同一聯絡點，便可取得某個範疇內全部所需的產品及服務。 | 顧客要同時尋找多家供應商，感到繁複。 |
| S22 | 白牌 | Whitelabel | 其他品牌可把由你製造的產品冠上自身名義出售。 | 生產能力強卻未有品牌或銷售渠道時。 |
| S23 | 成分品牌 | Ingredient Branding | 以著名的零件或原料品牌提高成品吸引力。 | 零件或原料在品質上有明顯優勢。 |
| S24 | 共同擁有 | Fractional Ownership | 讓多人共同持有昂貴而低頻使用的資產。 | 顧客既想持有又不常使用的高價資產，可考慮共同擁有。 |
| S25 | 買一捐一 |  | 每售出一件產品，便捐出一件給有需要的人。 | 以社會使命吸引顧客的品牌。 |
| S26 | 廢物變現 | Trash-to-cash | 把舊物回收後，可轉售或製作成新產品。 | 廢料來源穩定且目標顧客重視環保時。 |
| S27 | 長尾 | Long Tail | 不倚賴熱賣商品，而由大量小眾產品合計帶來收入。 | 可在上架及備貨開支偏低時，供應很多不同類別。 |
| S28 | 超級市場 | Supermarket | 在同一地方供應大量平價商品類別。 | 顧客想一次購齊，而你具備採購規模。 |

### 5.3 怎樣擴大與營運結構

| 編號 | 模式 | 英文名 | 說明 | 何時考慮 |
|---|---|---|---|---|
| S29 | 聯盟分銷 | Affiliation | 讓他人協助銷售並支付佣金，或代售他人產品收取佣金。 | 不增加銷售人手而又要擴闊銷售，可考慮聯盟分銷。 |
| S30 | 店中店 | Shop-in-shop | 利用合作夥伴店內的空間設點，分享位置和人流。 | 有意涉足實體零售卻不想自行開店時。 |
| S31 | 跨行加售 | Cross Selling | 利用既有顧客和資源，加售其他行業產品。 | 穩定顧客群若同時有相關的其他需要，可考慮跨行加售。 |
| S32 | 善用閒置資源 | Make More of It | 將內部知識或資產另作銷售。 | 公司有閒置空間、設備或專門知識。 |
| S33 | 群眾外包 | Crowdsourcing | 任務由大眾分擔，以小額獎勵或比賽作回報。 | 需要大量人手或創意，並能把任務分拆。 |
| S34 | 開放式合作 | Open Business Model | 與顧客、供應商或互補者合作產生價值。 | 單靠自己做不成，而夥伴各有長處。 |
| S35 | 統籌者 | Orchestrator | 自己專注核心環節，其餘工作交外部處理並加以統籌。 | 資源不多，想專心做好最擅長的部分。 |
| S36 | 整合者 | Integrator | 由自己控制價值鏈中大部分環節。 | 供應商抽成高或不可靠，而你能自行處理。 |
| S37 | 由推到拉 | From Push to Pull | 根據實際需求才開始生產，避免先行生產後再推銷。 | 存貨嚴重積壓且需求變化迅速時。 |
| S38 | 反主流定位 | Aikido | 採取與主流相反的價值主張，以吸引反對主流做法的顧客。 | 行業內做法相近，且部分顧客不滿主流安排。 |
| S39 | 反向工程 | Reverse Engineering | 以較少研發成本製成可相容或相近的產品，須先研究對手產品。 | 即使可以在已有成熟產品的市場以較低成本取得相近效果，亦須注意知識產權。 |
| S40 | 反向創新 | Reverse Innovation | 成熟市場亦可採用原本面向新興市場的平價產品。 | 已有在低成本市場證明可行的簡單產品。 |
| S41 | AI 輔助收購整合 |  | 以收購傳統服務企業為起點，藉 AI 重新編排工作流程，目標是改善毛利。 | 有可用資金，目標行業由大量小型服務公司構成，且其工作流程高度重複。 |

## 6. 改變方向檢查

構思方案前，逐一檢視生意模式九格內四處：若由此處改變，競爭方法是否會截然不同？每一處至少提出一個想法，再用模式卡落實。

| 位置 | 涵蓋九格中的 | 要問的問題 | 可參考的模式 |
|---|---|---|---|
| 價值主張 | 價值主張 | 能否由單次購買轉為持續服務？能否由賣工具變成直接交付結果？能否把單純銷售的做法轉化為平台？ | 訂閱制、AI 代辦成果、雙邊市場／平台 |
| 前台 | 顧客群、渠道、顧客關係 | 能否服務目前未被照顧的客群？能否透過新渠道大量觸及顧客？能否大幅增加顧客轉走的代價？ | 服務基層、聯盟分銷、店中店、鎖定、會員與忠誠計劃 |
| 後台 | 關鍵資源、關鍵活動、關鍵夥伴 | 能否形成難以仿製的資源，例如品牌、資料、知識產權或用戶群？能否借助他人資源來擴大？能否由重資產轉為輕資產運作？ | 授權／知識產權、特許經營、統籌者、善用閒置資源 |
| 收益公式 | 收入來源、成本結構 | 能否改用其他收費方式，例如重複收費、依用量、依成果或由第三方付款？成本結構能否作徹底改變，改按另一套架構運作？能否移除顧客不重視的項目來提升毛利？ | 訂閱制、按用量收費、按成果收費、廣告／第三方付費、極簡低價、極致奢華 |
